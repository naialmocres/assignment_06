The hardest part of this assignment was getting the pipeline to work as a whole. Each step returned data at a different grain: reviews, sentences, opinion targets, and entities. I had to keep the API extraction steps separate from the transformations, preserve each review_id, and follow the assessment references to connect an opinion target to the right words. I also had to combine opinion mining with named-entity recognition because people and products mentioned without an opinion word would otherwise be missed. I want more practice tracing nested JSON and checking intermediate DataFrames before joining them.

I also struggled with getting all the reviews into the app and understanding how the question feature should use them. Testing with the five sample reviews was useful, but it was not the same as running the full set and checking that the filters and counts reflected every review. The question box required a separate retrieval step: identify the items, locations, and subjects in a question, select matching evidence, and only then build a prompt for the reasoning model. I learned that the model should explain the evidence rather than do the counting; pandas should calculate the totals and item rankings. Next time, I would verify the full dataset and cache first, then test questions with a known item, a location, and a question with no matching evidence.

This assignment also helped me understand why API details matter. The Azure endpoints expect form data, while the decision and language-model endpoints expect JSON; `raise_for_status()` makes a failed request visible at the point where it happens. Caching keeps repeated pipeline runs from making unnecessary requests, and keeping the API key in an environment variable or `.env` file protects it from being committed. I still need more practice debugging the complete app flow, especially distinguishing a data or cache problem from a question-scope problem. I can improve by running one pipeline stage at a time, checking its row counts and columns, and then testing the app with small, predictable questions before relying on the full dataset.
